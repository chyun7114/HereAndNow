## 1. 테스트 목적

지도 기반 서비스에서 viewport 내 장소 조회 시 발생하는 성능 병목을 분석하기 위해,

**PostGIS 공간 조회 쿼리 자체의 성능**만을 분리하여 검증한다.

이번 테스트는 API 응답 시간이나 애플리케이션 전체 처리 시간이 아니라, 아래 요소들의 효과를 확인하는 데 목적이 있다.

- **GiST 기반 R-Tree 인덱스 적용 효과**
- **MBR 필터링 적용 효과**
- **조회 범위 크기에 따른 성능 변화**
- **데이터 규모 증가에 따른 성능 변화**

---

## 2. 테스트 범위

### 포함

- DB 내 공간 조회 쿼리 실행 시간
- 실행계획 변화
- 인덱스 사용 여부
- 후보군 축소 효과

### 제외

- Spring Boot 애플리케이션 처리 시간
- HTTP 네트워크 왕복 시간
- JSON 직렬화/역직렬화
- 캐시(Caffeine/Redis)
- 동시성 요청
- HikariCP 커넥션 풀 영향
- 프론트엔드 지도 이벤트 처리

즉, **오로지 SQL 실행 성능만 측정**한다.

## 3. 데이터셋 구성

| 구분          | Place   | Pin     | Course          | 비고               |
| ------------- | ------- | ------- | --------------- | ------------------ |
| 소규모 검증군 | 10,000  | 10,000  | 2,500 ~ 3,000   | 빠른 반복 테스트용 |
| 본 실험군     | 100,000 | 100,000 | 25,000 ~ 30,000 | 성능 차이 검증용   |

### 데이터 관계

- `Pin : Place = 1 : 1`
- `Course : Pin = 1 : N`
- 코스는 핀을 **1~7개** 가짐
- 코스당 평균 핀 수는 **약 3.5~4개** 수준으로 분포 구성

## 4. 비교군 정의

| 케이스       | 공간 인덱스(GiST) | MBR 필터링 | 목적                                  |
| ------------ | ----------------- | ---------- | ------------------------------------- |
| **Baseline** | X                 | X          | 최적화 전 순수 기준 성능              |

## 5. 테스트 시나리오

### 시나리오 A. 좁은 범위 조회

작은 viewport 범위 내 장소를 조회

- 목적: 후보군이 적은 상황에서의 성능 측정
- 특징: 차이가 크지 않을 수도 있음
- 의미: 작은 범위에서도 실행계획 차이가 발생하는지 확인

### 시나리오 B. 일반 범위 조회

실제 사용자 사용 패턴과 유사한 중간 크기 viewport 조회

- 목적: 대표 시나리오 검증
- 특징: 가장 현실적인 비교군
- 의미: 포폴의 핵심 결과로 활용 가능

### 시나리오 C. 넓은 범위 조회

넓은 지도 범위 내 많은 후보군을 포함하는 조회

- 목적: 후보군이 많을 때 성능 열화 정도 확인
- 특징: 최적화 효과가 가장 크게 드러날 가능성이 높음
- 의미: MBR과 인덱스의 필요성을 가장 잘 보여줌

### 시나리오 D. 데이터 규모 확장 비교

동일 조회 범위를 소규모/본 실험군 각각에 수행

- 목적: 데이터 증가에 따른 성능 변화 확인
- 의미: 최적화 효과의 확장성 검증

## 8. 측정 방법

| 항목      | 기준                                |
| --------- | ----------------------------------- |
| 실행 횟수 | 각 케이스당 30회 이상 반복          |
| 워밍업    | 최초 1~2회는 제외                   |
| 측정 대상 | 동일 bbox, 동일 데이터셋, 동일 환경 |
| 비교 기준 | 평균 / p95 / 실행계획 동시 비교     |
| 실행 환경 | 동일 DB 환경에서 수행방식           |

### 권장 측정 절차

1. 동일 데이터셋 준비
2. Baseline 쿼리 실행
3. 10회 반복 측정
4. 실행계획 수집
5. GiST 적용 후 동일 반복
6. GiST + MBR 적용 후 동일 반복
7. 결과 비교

## 9. 검증 목표

### 목표 1

**GiST 인덱스 적용 시 Baseline 대비 유의미한 실행 시간 감소가 나타날 것**

### 목표 2

**GiST + MBR 적용 시 GiST만 적용한 경우보다 추가적인 실행 시간 감소가 나타날 것**

### 목표 3

**조회 범위가 넓어질수록 Baseline과 최적화 쿼리 간 성능 차이가 더 크게 나타날 것**

### 목표 4

**데이터 규모가 10만 건으로 증가해도 최적화 효과가 유지될 것**

## 10. 기대 결과 해석 프레임

| 비교                   | 기대 해석                                       |
| ---------------------- | ----------------------------------------------- |
| Baseline vs GiST       | 공간 인덱스의 후보 탐색 비용 절감 효과          |

| 좁은 범위 vs 넓은 범위 | 후보군 수 증가에 따른 최적화 필요성 확인        |
| 10k vs 100k            | 데이터 증가 시 최적화 전략의 확장성 확인        |
